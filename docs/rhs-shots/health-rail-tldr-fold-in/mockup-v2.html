TL;DR writer contract (heartbeat prompt — keeps content, length, and look consistent)

  • Wire budget: the envelope rides transcriptTail; the 800-char wire cap is raised for the heartbeat monitor (generous backstop ~6000 — today's slice(-800) keeps the tail end, so an oversized envelope loses its [TL;DR …] head and fails parse). Envelope v4: [TL;DR HH:MM] {"v":4,"fleet":"…","repos":[{"repo","summary","blocker","signal"}]}. Length is guidance-driven, not char-capped: fleet reads well at 2–3 sentences (3-line clamp), repo summaries at 2–4 sentences; blocker ≤ 48 (parser slices). The writer decides based on content; the clamp is the renderer's safety net.
  • Content rule: fleet tells the cross-repo story: who needs the operator, why, and what unblocks it. repos[].summary narrates cause → blocker → next action. Never restate momentum, burn, or context numbers — the readings column renders those deterministically; a summary that repeats them wastes its 200 chars.
  • Mini-markup, not HTML: writer emits *strong*, `mono`, !alert!; the client renders these to styled spans through an allowlist. Raw HTML from a transcript is never injected (untrusted input — XSS boundary stays server-side of innerHTML).
  • Signals: ok · working · idle · needs-you · blocked · failed · all-clear — same enum tldrCardSignalClass already maps.
  • Overflow behavior: prose renders with a 3-line clamp; the writer should end sentences early rather than rely on the clamp. A summary that violates budget is clamped, never rejected — the deterministic finisher fallback still applies when no envelope parses.
