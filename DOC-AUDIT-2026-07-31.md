## 1. Method

Each doc was classified by checking its load-bearing claims against the current
tree — named symbols, file paths, commands, ports, endpoints, and config keys —
rather than by reading it for plausibility. Two mechanical sweeps ran across all
19 assessed files:

- **Every cited `src/`, `scripts/`, `tests/` path exists.** No path rot.
- **Every documented command exists** in `package.json` scripts or `scripts/`.

So the rot in this repo is not broken references. It is (a) plans that describe
work the code has since done differently, and (b) point-in-time observations
frozen into files whose names imply currency.

## 3. Contradictions that could mislead a contributor

Ranked by blast radius.

### 3.1 `DRAWER-STATES-PLAN` §5 orders preservation of four deleted functions

The plan states in bold that `renderOverview`, `renderSwarmSection`,
`renderTechnical`, and `renderTarget` "keep their names, order, and
`transcriptTail` placement." All four are gone from `src/web/app.js` (0
occurrences each), and `tests/web-client.test.ts:5212` asserts their removal:

```js
expect(byClass(drawer, "swarm-section")).toBeNull();
```

A contributor obeying the doc would reintroduce dead code and turn the suite
red. This is the single most dangerous document at the root.

### 3.2 Onboarding docs vs. the deploy rulebook (**corrected**, §5)

`README.md` and `QUICKSTART.md` documented `bun start` as binding **4702**,
"so it never collides with a production instance." Commit `078e016`
(2026-07-28) changed `scripts/anthill-start.sh:15` to
`PORT="${MOUNTAIN_PORT:-4701}"` — the launchd production port that
`DEPLOY.md` says to **never** launch on by hand. The safety claim was
inverted, and two onboarding docs instructed readers to violate the third.

### 3.3 `SECURITY.md` understated its own defenses (**corrected**, §5)

The doc warned that `/api/broadcast` dispatches `instruct` without the
30-second freshness check. `src/server/broadcast.ts:86` enforces
`MAX_CONTROL_SNAPSHOT_AGE_MS` and returns `STALE_SNAPSHOT` at :91, before
`executeControl` at :111. An operator reading this would wrongly believe
broadcast was unprotected.

### 3.4 `SIGNAL-SURFACE` asks for a surface that was deliberately removed

Acceptance criterion "Conductor never disappears" is falsified by commit
`40e525e`, whose message states "AttentionBoard type deleted … `#attention-board`
is gone." `attentionBoard`, `renderAttentionBoard`, and `allClear` are all 0
occurrences. The doc is also the only root file still presenting
`signal-surface-hybrid.html` as a "pixel target."

### 3.5 Two docs claim the same DOM slot

`SIGNAL-SURFACE` §F2 assigns `#attention-board` to the slot above the workboard
split. That slot is now `#health-rail` → `#health-widgets` + `#pulse-findings`
(`src/web/index.html:44-50`). Nothing tells a reader which doc won.

### 3.6 `GOAL.md` states a Cursor compliance rule the code contradicts

`GOAL.md:17` treats "reported non-Grok models" as violations.
`config/models.json` `cursorNativeFamilies` admits `composer-2` and
`composer-2.5`, and `README.md:38` was deliberately widened to "Grok and
Composer families" in `bfe717c`. Under GOAL a compliant session reads as a
violation.

### 3.7 Stale model-routing instructions

`BODY-RESTYLE-PLAN` and `SIGNAL-SURFACE-HYBRID-PLAN` contain copy-pasteable
launch commands pinning explicit models (`--model opus-4.8`,
`--model gpt-terra`). Current policy is that subagents inherit the session
model. Both read as authorization to violate it.

## 6. Open questions for a human

**A token-truth policy may have drifted without being recorded.**
`VITALS-COLLECTORS-BE-HANDOFF.md` established that `contextWindow` must only be
emitted when the source reports it — "a missing window must stay absent, not a
hardcoded 200k/250k." `src/server/collectors.ts:599` now emits a `contextWindow`
for Claude derived from a model-id lookup table (`claudeContextWindows` in
config). The `[1m]` marker handling is carefully commented and clearly not
careless, so this is probably a reviewed decision — but it is the exact shape
the handoff forbade, and no doc records the reversal. Worth confirming it was
intentional.

**`DEPLOY.md:19` is currently untrue as an operational fact.** It states that
:4701 serves the `the-mountain-main` worktree on branch `main`. Because the
launchd job pins `WorkingDirectory` to this worktree with `KeepAlive`,
production serves whatever branch is checked out — and at audit time that was
`fix/backend-silent-failures-and-freshness`. `anthill-deploy.sh` would refuse to
deploy in this state, which is the guard working, but the doc gives no way to
detect or recover from it.
