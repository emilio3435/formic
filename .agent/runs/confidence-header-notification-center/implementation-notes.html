Decisions the spec did not make

R1 · Dead time is dropped entirely — not withheld

The panel was designed around a standby hero: how long each agent has been waiting. That number does not exist. Measured live (docs/S0-T1-DEAD-TIME-MEASUREMENT.md): hookLifecycleAt advanced 01:38:51 → 01:39:16 → 01:40:41 on a session that stayed needsInput throughout, so it is a write clock. The fallback candidate died too — agent.hook.Notification.occurred_at repeats mid-wait (seq 99281 then 99477 while the state held), so it would reset the age inside a single wait. The cmux journal rolls over, so the history to reconstruct it is not there either.

So the hero and every per-row age were deleted, not rendered as withheld-with-a-reason. Withholding was right while the field was merely unmeasured; once the answer is "this cannot be obtained from these sources", a permanent apology in the largest type on the panel is furniture that implies the number is coming. The count leads instead. pulse.blocked ships; standbyMs and blockedSince do not.

R2 · The board never deletes

The Clean up chip runs the sweep's propose phase only. Its output becomes a notification item listing each removable item, its rollback SHA, every refusal with its reason, and the exact confirm command to paste. No destructive server endpoint, now or later. A click in a browser is not the same gate as a person reading a plan in a terminal. Enforced structurally: a test reads app.ts, cleanup-propose.ts, the worker and index.ts as source text and asserts confirmCleanup, worktree remove, branch -d/-D and --force appear in none of them, then fetches /api/cleanup/confirm and asserts 404.

R3 · Consumption publishes as a covered floor

The all-terms-observed gate would have withheld the Tokens card permanently — 40 of 384 sessions never report tokens (38 Cursor), three of them live. A card that can never render is worse than no card. But the rule was never "withhold when incomplete"; it is "never present a partial as if it were complete". Two precedents already existed in this codebase: Burn publishes its rate with coverage{reporting,eligible,unknown}, and Cost publishes with costIsFloor rendering ≥. So consumption publishes the covered subtotal, carries consumptionReporting/consumptionEligible, and marks itself a floor. A duration for one agent cannot be a floor — which is why standbyMs stays absent and R1 is unaffected.

Other decisions

  • Cleanup sweep model → Grok 4.5 High Fast, not GPT 5.6 Luna. The routing table puts mechanical sweeps on Grok; Luna is for read-only investigation.
  • Cleanup autonomy → propose-then-confirm. Per-item rollback SHAs, occupancy evidence, git branch -d never -D, and a live agent process inside a worktree is a hard stop regardless of approval.
  • Board-side marks → a separate plan. Not this program.
  • The scan-window statement lives in the summary rail's header, not the toolbar's #scope-note — that line vanishes on Usage and is a live region that changes with filters, and putting a stable board-wide fact into a volatile filter line makes the stable fact inherit the volatility.
  • S0-T4 shipped nothing. attentionSignal.evidence fails as the ask in 3 of 5 live blocking sessions, but the remedy (blockedAsk) was proven only synthetically. A clipped evidence line degrades; a reconstructed ask is wrong. Recorded as a limitation, not patched with a guessed field.

Changes made because the repo disagreed with the plan

  • The plan's §6 claim "an unmeasurable duration is withheld, not zeroed" is superseded by "the order is stable across paints and never depends on a duration" (R1).
  • The plan assumed one PR. The branch is shared with a second program, so work shipped as five tranches, each verified green and merged separately.
  • A concurrent lane's finding-links feature was landed first and credited (4bcbd84) so S2-T1 could remove it in a commit that names it, rather than silently reverting it.
  • A stalled snapshot.ts fix from another lane was landed (6cc27bc) because leaving it dirty forced a lane to weaken a wire type to route around a fixture it was fenced out of.

Tradeoffs and things worth knowing

  • Consumption is legitimately absent until the first session scan completes. A freshly started board shows no Tokens card for a minute or two. This is correct — do not add a loading state implying otherwise, and never fall back to totals.tokens (occupancy).
  • An absence proves nothing until you know the process. I twice concluded consumption was broken; both readings were against a server that either predated the change or had not finished its first scan. Record the PID and its start time before drawing a conclusion.
  • Shared-worktree git: git add <paths> && git commit commits the whole index, including other agents' staged hunks. It buried 835 insertions of another lane's work under a server-fix message once. Always git commit -F - -- <paths>, and check git diff --cached --stat first.
  • controlHealth has a blind spot. It can report five healthy sources while sessionCollectionComplete is false, because they read different populations. The operator reads that chip as "instruments fine". Worth its own work.
